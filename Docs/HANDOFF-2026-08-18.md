## The corpse bug I found while you were asking about it

You asked whether lootable bodies should be showing. They would not have worked
even once deployed, and it was my error.

`ADCCCharacterBase::CorpseLifeSpan` is 0 (keep forever) — I checked that and
reported it. But **`ADCCEnemyCharacter` overrides it to 8 seconds**, and enemies
are the only things that carry loot. Every lootable body would have deleted itself
eight seconds after dying.

Fixed as a policy rather than a number:

- A body **with loot on it waits indefinitely**
- Once **emptied**, it starts a 25-second despawn (`LootedCorpseLifeSpan`)

Loot is safe from a timer, and a cleared room still cleans itself up — which also
helps the framerate problem below.

## Performance — the culprit, with numbers

Your level is **not** too busy: **236 placed actors**, matching the 260 loaded. The
1700 Thai_Market and 1052 Viking_village actors belong to those packs' demo levels
and never load during PIE.

**It is texture memory.**

| Pack | Size | In the playable level? |
|---|---|---|
| **Cave_Camp** | **1.76 GB** | **Yes — Room 01 is built from it** |
| Legendary_Forge | 1.25 GB | Yes |
| Modern_villa_kit | 1.12 GB | Yes |
| Ice_Station | 774 MB | Yes |
| Diner | 656 MB | Yes |

**1713 MB of Cave_Camp's 1762 MB is textures** — 97% — and **12 individual textures
exceed 40 MB**, several at 92–99 MB. A 99 MB normal map is an uncompressed 8K
texture, and there are three of those just for cave rocks.

That explains all three symptoms at once: GPU 99% (texture bandwidth), the memory
pressure warning (streaming pool thrashing), and 7 FPS. It is also why builds are
slow — the same RAM exhaustion.

### The fix — needs MCP, queued

Set **Maximum Texture Size = 2048** on the 12 oversized Cave_Camp textures. At
gameplay distance you will not see a difference on a cave wall, and it cuts each
from ~99 MB to ~6 MB — roughly **1.1 GB reclaimed in one pass**. Nothing is
deleted; it is a per-asset import setting and fully reversible.

Smaller free win: the project still holds **both** `SK_ArmsOut`/`SK_ArmsOut_Shared`
and `SK_DiceWinged`/`SK_DiceWinged_Shared` at ~26 MB each. The originals were kept
as fallback until the Blueprints were repointed — that is done, so ~52 MB can go.

### What I fixed in code

The escort AI was doing a **full world scan every tick per ally**, and idle enemies
were re-scanning the entire world every frame looking for a target. With 236 actors
that is thousands of actor visits per frame — a regression I introduced with the
escort behaviour. Both are now cached and refreshed on a **staggered** interval, so
enemies do not all rescan on the same frame and turn a steady cost into a hitch.

Expect this to help the CPU side. It will not fix GPU 99% — that is the textures.

## New tonight

### `ADCCGameMode` — the P0 multiplayer blocker

The roadmap's number one item. There was no join path at all: one PlayerStart, no
spawn selection, `PostLogin` left to the engine default. Five people connecting
meant five crawlers inside one another.

- **Late joiners route to a Safe Room.** `ADCCRoom::AllowsAsyncLogin()` has derived
  this from room type since it was written and has been waiting for a caller.
- **Otherwise the emptiest PlayerStart wins** — ranked by distance to the nearest
  living crawler, not "first one free", because a start can be unoccupied and still
  be two metres from somebody.
- `GameStateClass` and `HUDClass` are now **C++ defaults**, so the pause loop can no
  longer silently do nothing because a Blueprint forgot to set them.
- Warns in the log if the best available start is still crowded, so "add more
  PlayerStarts" is a message rather than a mystery.

**One manual step:** reparent `BP_ThirdPersonGameMode` to `ADCCGameMode`
(`BlueprintTools.set_parent`). Needs MCP. Until then it runs as before.

### Audio hooks

You have zero audio, and the reason was never that nobody wanted any — there was
nowhere to put a sound once you had one. Six `USoundBase` slots now sit on the
multicast paths that already exist for animation, so a clip assigned in the Details
panel is heard on every machine with no further wiring:

`AttackSound`, `HurtSound`, `DeathSound`, `DownedSound`, `ReviveSound`, `CastSound`

All optional — null is silence, exactly as today. Grab the Sonniss archive and these
become a drag-and-drop job.
